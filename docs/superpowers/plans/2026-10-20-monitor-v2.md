# Monitor v2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Acrescentar ao Monitor: VMs com nome legível, aba Portas com "Liberar porta", containers do Docker, histórico de picos, alerta de descontrolados, custo da sessão do Claude e reiniciar app.

**Architecture:** Toda regra nova entra no `MonitorCore` como tipos puros testáveis (parsers, tabelas, rastreadores, gravador de picos) com efeitos colaterais isolados atrás de protocolos (executor de comandos, relógio). O `MonitorStore` orquestra a coleta; a janela ganha abas Portas, Docker e Picos.

**Tech Stack:** Swift 6.2, SwiftUI, AppKit, Swift Testing (via `scripts/test.sh`), CLI `docker` e `lsof` do sistema. Sem dependências novas.

**Spec:** `docs/superpowers/specs/2026-10-20-monitor-v2-design.md` (estende `docs/superpowers/specs/2026-10-20-monitor-memoria-design.md`). Ler ambos.

## Global Constraints

- Tudo da v1 continua valendo: macOS 14+, sem Xcode, sem dependências de terceiros, pt-BR, tema escuro do mockup, **zero comentários no código**, commits em inglês sem coautoria, nunca fechar nada sozinho.
- Consumo do app continua abaixo de ~50 MB e CPU desprezível em repouso.
- Descontrolado CPU: ≥ 80% contínuo por ≥ 5 min. Memória: crescimento contínuo por ≥ 30 min somando ≥ +50% **e** ≥ +500 MB.
- Só processos do próprio usuário e fecháveis geram alerta de descontrolado; daemons de build não geram alerta de CPU.
- Histórico de picos: guarda 7 dias; top 5 grupos por app no momento da pressão máxima.
- Containers: coleta a cada 15 s e só com a janela aberta; contagem para confirmação consultada na hora.
- Porta de container: liberar = parar só o container, com confirmação; nunca sair do Docker por causa de porta.
- Custo da sessão: sessão + subárvores dos filhos que contêm um servidor MCP; não inclui servidores de dev.
- Reiniciar: só apps com janela; se não fechar em 20 s, não reabre e avisa.
- CLI do Docker: `/usr/local/bin/docker`, com fallback `/Applications/Docker.app/Contents/Resources/bin/docker`; timeout de 5 s.

## Review Focus

- `docker` ausente, travado ou Docker fechado: lista de containers vazia em até 5 s, sem travar a coleta. (teste na Task 3)
- Mesma porta escutando em IPv4 e IPv6 pelo mesmo processo: uma linha só, exposição "aberta na rede" se qualquer endereço for de rede. (teste na Task 1)
- Porta liberada enquanto a confirmação está aberta, ou processo que já terminou: resposta "Porta livre" / "O processo já tinha terminado.", nunca sinal para outro processo. (teste na Task 4)
- PID reutilizado no rastreador de descontrolados: histórico zera, sem alerta herdado. (teste na Task 5)
- Arquivo de picos corrompido ou ausente: começa vazio, sem travar; próxima gravação sobrescreve. (teste na Task 6)

### Task 4: Tabela de portas e liberar porta

**Files:** Create `Sources/MonitorCore/Ports/PortTable.swift`; Test `Tests/MonitorCoreTests/PortTableTests.swift`

**Interfaces:**
- Consumes: `ListeningSocket` (T1), `DockerContainer` (T3), `ProcessRow`, `ProcessGroup`, `TerminationPlanner`.
- Produces: `public enum PortOwner: Sendable, Equatable { case process(ProcessRow); case container(DockerContainer) }`; `public struct PortEntry: Sendable, Identifiable, Equatable { id: String ("port-pid"); port: UInt16; exposure: Exposure; owner: PortOwner; title: String; project: String?; startTime: Date? }`.
- Produces: `public enum PortTable { public static func build(sockets: [ListeningSocket], rows: [ProcessRow], containers: [DockerContainer]) -> [PortEntry]; public static func release(port: UInt16, entries: [PortEntry], all: [ProcessSnapshot], myUid: UInt32) -> PortRelease }`.
- Produces: `public enum PortRelease: Sendable, Equatable { case free; case stopContainer(id: String, name: String); case close(ProcessGroup); case blocked(String) }`.
- Regras: socket cujo processo pertence ao Docker (`identified.appBundlePath == Classifier.dockerAppPath`) e cuja porta está em `publishedPorts` de um container → dono = container, `title` = nome do container, `project` = compose; senão dono = processo, `title`/`project` do `Identified`. ### Task 5: Descontrolados

**Files:** Create `Sources/MonitorCore/Runaway/RunawayTracker.swift`; Modify `Sources/MonitorCore/Prefs/NotificationPolicy.swift`; Test `Tests/MonitorCoreTests/RunawayTrackerTests.swift`

**Interfaces:**
- Produces: `public enum RunawayReason: Sendable, Equatable { case cpu(minutes: Int); case memory(from: UInt64, to: UInt64, minutes: Int) }`; `public struct Runaway: Sendable, Identifiable, Equatable { id: Int32; row: ProcessRow; reason: RunawayReason; public var hint: String }` com textos `"CPU acima de 80% há N min."` e `"Memória cresceu de X para Y em N min."` (X/Y via `Format.bytes`).
- Produces: `public struct RunawayTracker: Sendable { public init(); public mutating func update(_ rows: [ProcessRow], at now: Date, myUid: UInt32, ignore: IgnoreList) -> [Runaway] }`.
- Regras: histórico por chave `pid + startTime` (PID reutilizado zera). CPU: sequência contínua de amostras ≥ 80 cobrindo ≥ 300 s; qualquer amostra < 80 zera. Memória: janela das amostras dos últimos ≥ 1800 s em que nenhuma amostra caiu mais de 5% em relação à anterior; alerta quando `último ≥ primeiro × 1,5` e `último − primeiro ≥ 500 MiB`. Excluídos: `uid != myUid`, `kind == .system`, itens ignorados; daemons de build (argumentos ou nome contendo `gradle`, `kotlin-daemon`, `bazel`, `cargo`, `swift-build`, `tsc --watch`, `rustc`, `clang`) não geram alerta de CPU.
- Produces: `NotificationPolicy.evaluate(level:suspects:runaways:now:)` com `runaways: [Runaway] = []`; `AlertKind.runaway(IgnoreKey, title: String, hint: String)`; uma vez por chave enquanto continuar presente (conjunto separado dos esquecidos; persistido junto em `seen` com prefixo `runaway:`).

### Task 6: Histórico de picos

**Files:** Create `Sources/MonitorCore/Peaks/PeakRecorder.swift`; Test `Tests/MonitorCoreTests/PeakRecorderTests.swift`

**Interfaces:**
- Produces: `public struct PeakItem: Codable, Sendable, Equatable { title: String; bytes: UInt64 }`; `public struct PeakEpisode: Codable, Sendable, Identifiable, Equatable { id: UUID; start: Date; end: Date?; maxLevel: Int (rawValue de PressureLevel); maxPressure: Int; top: [PeakItem] }`.
- Produces: `public struct PeakRecorder: Sendable { public init(episodes: [PeakEpisode] = []); public private(set) var episodes: [PeakEpisode]; public mutating func update(stats: SystemStats, groups: [ProcessGroup], at now: Date) -> Bool }` (retorna `true` quando algo mudou e precisa salvar).
